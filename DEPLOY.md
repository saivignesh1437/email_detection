# Deployment Guide: Render Platform

This document describes how to deploy the **Intelligent Email Detection and Management Platform** to [Render](https://render.com) using the included `render.yaml` Blueprint or manual service setup.

---

## 1. System Architecture on Render

The platform comprises four coordinated services:

```
┌────────────────────────────────────────────────────────┐
│             Render Static Site (CDN)                   │
│             email-detection-frontend                   │
│             (React 19 + Vite 8 SPA)                    │
└──────────────────────────┬─────────────────────────────┘
                           │ HTTPS (VITE_API_URL)
                           ▼
┌────────────────────────────────────────────────────────┐
│             Render Web Service (Public)                │
│             email-detection-backend                    │
│             (FastAPI + Scikit-Learn ML)                │
└──────────────┬──────────────────────────┬──────────────┘
               │                          │
               │ PostgreSQL Wire          │ HTTPS Public URL
               │ (DATABASE_URL)           │ (DSA_ENGINE_URL)
               ▼                          ▼
┌──────────────────────────────┐  ┌──────────────────────────────┐
│ Render PostgreSQL Database   │  │ Render Web Service (public)  │
│ email-detection-db           │  │ dsa-spam-engine              │
│ (Relational 3NF + Triggers)  │  │ (Java 21 DSA Docker Engine)  │
└──────────────────────────────┘  └──────────────────────────────┘
```

| Service | Render Type | Runtime / Image | Plan Tier | Public Access |
|---|---|---|---|---|
| **Frontend** | Static Site (`web`) | `static` (Vite build) | Free | Public CDN |
| **Backend** | Web Service (`web`) | `python` (FastAPI / Uvicorn) | Free | Public HTTPS |
| **Java DSA Engine** | Web Service (`web`) | Docker (`eclipse-temurin:21`) | Free | Public HTTPS |
| **Database** | PostgreSQL (`databases`) | PostgreSQL 16+ | Free | Internal / External SSL |

The Java engine is configured as a public free web service because Render does not offer free private services. Its `/analyze` endpoint is publicly reachable and has no authentication; do not submit private email content. The engine binds to `0.0.0.0` and Render's `PORT` (10000 in this Blueprint), while local use defaults to port 8080. Free services can spin down when idle.

## 2. One-Click Blueprint Deployment (Recommended)

1. **Push your repository** to GitHub or GitLab.
2. Log in to the [Render Dashboard](https://dashboard.render.com).
3. Click **New +** in the top navigation and select **Blueprint**.
4. Connect your Git repository.
5. Render will automatically parse [`render.yaml`](./render.yaml) and present the resource creation plan:
   - `email-detection-db` (PostgreSQL Database)
   - `dsa-spam-engine` (Java Web Service, public URL)
   - `email-detection-backend` (FastAPI Web Service)
   - `email-detection-frontend` (Static Site)
6. Click **Apply**. Render will provision the database, generate a secure `SECRET_KEY`, and build all services.

## 3. Environment Variables Reference

### Backend (`email-detection-backend`)
| Variable | Description | Example / Source |
|---|---|---|
| `ENVIRONMENT` | Deployment environment mode | `production` |
| `DATABASE_URL` | PostgreSQL connection string | Injected automatically from `email-detection-db` via `fromDatabase` |
| `SECRET_KEY` | Cryptographic secret for signing JWT tokens | Auto-generated by Render (`generateValue: true`) or 64-char hex string |
| `DSA_ENGINE_URL` | URL to reach the Java DSA engine | `https://dsa-spam-engine.onrender.com` |
| `ALLOWED_ORIGINS` | Comma-separated CORS allowed origins | `https://email-detection-frontend.onrender.com,http://localhost:5173` |
| `PORT` | Listening port for Uvicorn | Injected automatically by Render (defaults to `10000`) |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | JWT expiration duration in minutes | `1440` (24 hours) |

### Java DSA Spam Engine (`dsa-spam-engine`)
| Variable | Description | Value |
|---|---|---|
| `PORT` | Listening port assigned to Java web service | Render sets this (10000 in this Blueprint) |
| `DSA_HOST` | Network interface binding | `0.0.0.0` |

### Frontend (`email-detection-frontend`)
| Variable | Description | Example |
|---|---|---|
| `VITE_API_URL` | Public base URL of the FastAPI backend | `https://email-detection-backend.onrender.com/api` |

*(Note: The frontend code automatically normalizes `VITE_API_URL`, so whether you provide `https://...` or `https://.../api`, routes are resolved correctly).*

## 4. Safe Database Initialization

### Why not run `database/schema.sql`?
The local development `database/schema.sql` begins with `DROP TABLE IF EXISTS ... CASCADE;`. Running it against a live database drops all existing tables and wipes user data.

### Production Setup Order
To safely initialize a new database without data loss risks, use the non-destructive initialization script which applies:
1. **Tables** with `CREATE TABLE IF NOT EXISTS` (`users`, `categories`, `emails`, `spam_detection`, `email_audit_log`, `dsa_detection`)
2. **Indexes** with `CREATE INDEX IF NOT EXISTS` (including full-text GIN index `idx_emails_fts`)
3. **Stored Procedures & Functions** with `CREATE OR REPLACE FUNCTION` (`fn_get_user_email_stats`, `fn_get_system_dashboard_stats`)
4. **Triggers** with `DROP TRIGGER IF EXISTS` + `CREATE TRIGGER` (`trg_audit_email`, `trg_auto_categorize_spam`)
5. **Baseline Categories** (`Primary`, `Social`, `Promotions`, `Updates`, `Spam`) with `ON CONFLICT DO NOTHING`

> **Security Note:** The production setup **does not** create default demo accounts (`admin@emailmgmt.local` / `Admin@1234`) or hardcoded passwords. Users must register their own accounts via the app UI.

### Initialization Methods

#### Option A: Run via Render Shell (Easiest)
1. In the Render Dashboard, navigate to `email-detection-backend`.
2. Click the **Shell** tab to open an SSH terminal in the running container.
3. Run:
   ```bash
   python -m database.init_db
   ```
4. Verify the output displays `[SUCCESS] Database initialization completed successfully`.

#### Option B: Direct psql Connection
1. From the `email-detection-db` dashboard, copy the **External Database URL**.
2. Run from your local terminal:
   ```bash
   psql "<EXTERNAL_DATABASE_URL>" -f database/init_production.sql
   ```

## 6. Post-Deployment Verification Checklist

Once the services are deployed and the database is initialized:
- [ ] **Health Checks**: Access `https://<backend-url>/api/health` in your browser. Confirm `"database": "healthy"`.
- [ ] **User Registration**: Open `https://<frontend-url>/register`. Register a new account.
- [ ] **Authentication**: Log in with the newly created account. Verify the JWT token is saved and the dashboard loads.
- [ ] **Live Spam Detection**:
  - Compose a new email with subject `"Urgent prize winner"` and body `"Claim your free cash lottery prize now"`.
  - Send the email and verify it is quarantined into the **Spam** folder with both ML indicators and Java DSA keyword badges.
- [ ] **Reports & Analytics**: Navigate to the **Email Intelligence** analytics page. Confirm the daily activity trend, concordance ribbon, and model holdout metrics render without database errors.

## 7. Known Considerations & Troubleshooting

1. **Free Tier Cold Starts & Database Lifetime**:
   - Render Free web services spin down after inactivity, so initial requests can be slow while a service wakes.
   - Render Free PostgreSQL databases expire after 30 days and do not include backups. Treat this as a temporary demo, export data you need, and confirm current limits in Render before creating resources.
2. **Public Java API**:
   - The Java engine has no authentication and its URL is public. Anyone who discovers it can call `/analyze`; do not send private email content to this demo deployment.
3. **CORS Configuration**:
   - If frontend requests fail with a CORS error in the browser console, check the `ALLOWED_ORIGINS` environment variable in the backend settings. Ensure it contains the exact frontend URL (e.g. `https://email-detection-frontend.onrender.com`) without a trailing slash.
4. **ML Model Files**:
   - The Scikit-Learn model artifacts (`ml/model/spam_classifier.joblib`, `ml/model/tfidf_vectorizer.joblib`, and `ml/model/evaluation_metrics.json`) are committed to Git and loaded automatically into memory on backend startup.
5. **Environment Isolation**:
   - `.env` files and local PID files (`.backend.pid`, `.dsa_engine.pid`, `.frontend.pid`) are excluded from Git via `.gitignore` to prevent credential exposure.
